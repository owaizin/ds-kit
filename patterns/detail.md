# Detail: one record, clear priorities

Use when the user needs to understand and act on one object.

## Assemble

Begin with a route back to the collection, then record identity, labelled state and the main action. Show the facts that affect the decision before secondary activity. Use a description list for label/value facts and a table when comparing line items.

At wide widths a secondary activity/context column may sit alongside the main content. Keep its width/contrast subordinate to the primary record. On narrow screens place it after the facts and main content. A timestamp pairs with its event, not a detached decorative line.

Use a single content rail for header, facts and line items. Quantities align to the end with tabular numerals; long descriptions wrap. Distinguish totals through weight/separation, without enlarging every number. Attachments have a clear name and named download action; no unlabeled paperclip-only affordance.

## States and foundation mapping

Keep status text visible even if a semantic badge is used. An unavailable action explains why; a primary action returns a useful outcome. Loading/failure belongs to the affected region. Confirmation dialogs need an explicit focus/cancel contract if present.

Use the composition guide's page/section roles, base-4 step 6 region gaps/insets and step 8 major gaps. Static fact groups usually need only a divider, while an independently scoped object may use a panel. Activity can use muted body text with stable timestamp alignment.

## Acceptance

Check long record titles, zero attachments, multiline facts, large amounts and activity timestamps. At 375px retain the primary action and all unique facts. Verify action feedback and keyboard order. Compare prioritization, label/value alignment and restrained surface treatment against a rendered detail benchmark.
